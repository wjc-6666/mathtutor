# MathTutor V1.2：技术选择与运行方式

比较以 Windows/CPU、中文数学 OCR、约 3471 个旧片段为前提。质量判断最终以本地 benchmark 为准。

| 方案 | 优点 | 代价/限制 | 决策 |
|---|---|---|---|
| V1.1.1 BM25 + 字符 hash 基线 | 无额外模型，编号/原词可靠 | hash 不是语义；改写弱 | 完整保留回退 |
| BM25 + dense | 术语与改写互补；小规模可直接矩阵乘法 | OCR 公式会干扰语义，需要本机验证 | 采用量化 E5 CPU |
| 加 reranker | 可利用编号、内容类型和数学术语 | 神经交叉编码器另需模型/CPU预算；未证明必要 | 采用本地可解释规则重排，未装神经 reranker |
| Parent/Child | 能恢复完整题目/证明与邻近页 | OCR 缺编号时父级边界只能保守判断 | 采用有限跨页父级及 section 标识 |
| 轻量数学关系层 | 方法、定理、先修与例题导航可解释 | 不能把术语共现冒充正确数学推理 | 独立 JSON 图，显式区分系统整理/推断 |
| ColBERT / late interaction | token 级 MaxSim 能细粒度匹配 | 更多向量和运行依赖，中文数学模型另需评估；此规模暂不值得 | 暂不部署 |

不引入 Neo4j 或通用 GraphRAG 全流程。Microsoft GraphRAG 的全局/局部/DRIFT 思路作为导航参考，不用付费 LLM 批量抽图。未对 LazyGraphRAG、DRIFT、ColBERT 做本机质量比较，不把技术调研称作实测。

## 本地模型

- 基础模型 `intfloat/multilingual-e5-small`（MIT）；ONNX 转换仓库 `Xenova/multilingual-e5-small`。
- 固定 revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`。
- int8 权重 118,308,185 字节；tokenizer 17,082,730 字节；配置 1101 字节。合计 135,392,016 字节（约 129.1 MiB）。仅下载这些文件。
- CPUExecutionProvider，4 个推理线程；query/passage 前缀、attention-mask mean pooling、L2 归一化；384 维，最长 384 token。
- 不装 torch/SentenceTransformers；可选依赖见 `requirements-v12.txt`。运行期间不联网下载，不调用检索 LLM。
- OCR 正文与有文本依据的术语标签供语义编码；广告行与单纯公式行不占据语义编码预算。原始 OCR、公式、PDF 保持完整。
- 模型文件大小和 SHA256 在加载时校验；模型身份/索引表示版本不匹配即回退。语义模型不是公式计算器。

## 索引与回退

旧 SQLite `data/mathtutor.sqlite3` 保存的 documents/chunks/vectors 没有覆盖。V1.2 只读取原表，写入 `data/index/v12/generations/<generation>`：`knowledge.json`、`vectors.npy`、`manifest.json`。原子更新 `active.json`；失败不会覆盖旧 generation。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-v12.txt
# 仅在本地模型缺失时执行；固定约136MB文件，不下载整个仓库
.\.venv\Scripts\python.exe scripts\download_e5.py
.\.venv\Scripts\python.exe -m app.cli index-v12
.\.venv\Scripts\python.exe -m app.cli benchmark-v12
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.\data\pytest-temp
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`index-v12` 不调用 OCR、不扫描/重建 V1.1.1。新教材经旧扫描索引后，需要再次执行 `index-v12`；期间自动回退。聊天工具栏可选择 V1.1.1；也可设置 `RETRIEVAL_VERSION=v11` 后启动。旧 `/api/retrieval-debug` 原样保留，用来比较基线。

## 数据结构与解释

- `records`：旧 chunk，另将解答书中可靠识别的行首习题编号拆成子记录；保留 `source_chunk_id`。
- `parents`：同编号长块及有限续页合并。`sections`：原索引 section 对应子记录列表；章节仅当当前文本明确有章标题时保留。
- `entities`：Concept/Theorem/Method/ProblemType/Example/Exercise。
- `edges`：USES_METHOD、USES_THEOREM、TESTS 有原 chunk/page/术语语句依据，但仍标为系统推断。通用 APPLIES_TO、REQUIRES、PREREQUISITE_OF 属于系统整理，非教材引文。不能据此断言题目数学条件成立。
- SIMILAR_TO 在查询时按表面、概念/定理、方法三组生成，带 confidence 与原因；不写入永久图。低置信度关系不持久化。
- 元数据不可靠字段为 null；前后邻块和原 PDF 页码与旧库保持一致。chapter 不延用目录误判出来的章名。

QueryProfile 使用词表/条件表述规则，不声称可以理解任意数学题。扩展视角明确标出用户术语与系统假设。候选通道分别召回，再用 RRF 保留至多 50 个，依据原句 BM25、真实语义、扩展、编号、元数据、关系证据重排。编号完全匹配优先于正文引用。

EvidenceBundle 区分直接命中、理论、相似题、方法、父级与原页，然后传给保留四种模式的 Tutor。离线模式只生成本地知识导航/候选思路，不伪造完整推导或自动批改结论。

## API

- POST `/api/retrieval-debug-v2`：profile/expansion/候选/分数/关系/EvidenceBundle。
- POST `/api/similar-problems`：三类相似题。
- GET `/api/knowledge-map`：方法和主题列表、图统计。
- GET `/api/topics/{name}`：触发信号、先修、相关定理、教材例题及原页。
- GET `/api/retrieval-status`：实际索引版本、模型状态、回退原因。
- `/api/chat` 增加可选 `retrieval_version=auto|v11`，兼容原客户端。
- 旧 PDF `/pdf#page=N`、`/page/N`、上传、聊天历史、Vision API 保留；N=1 为第一 PDF 页，不采用印刷页码。

## Benchmark 限制

`tests/retrieval_benchmark.json` 是 35 题七类的人工探索集，按原 PDF 页核验，包含相关改写，不是独立留出集。相关页标注可能不穷尽所有正确出处，公式损坏可能导致失败。报告不删除失败案例，也不把某页答案写入检索规则。Recall 针对给定相关页集合，MRR 截断于前十个原始返回 chunk；一题一页时 Recall 等于该题命中率。
